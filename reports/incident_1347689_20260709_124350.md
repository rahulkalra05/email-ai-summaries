# Operational Incident Investigation Report

## ⚠️ Verdict

## Reported Issue Summary
A teacher is experiencing an issue where "Lock" rules created under "Manage Student Access" for the course *Ready, Set, Grow! (American English) Level 1* (Home Practice section) are not taking effect. Although the interface displays a confirmation message indicating the rule was saved successfully, the designated exercises remain fully accessible to students as if no restriction had been applied.

- **Affected Component:** Manage Student Access (Lock/Unlock Rules Engine)
- **Path of Affected Course:** Materials > Manage Student Access > Home Practice
- **Affected User Role:** Teacher

## Common Patterns Identified
- **Platform-wide Rule Corruption:** Multiple historical cases (Ticket 1299299, Ticket 1312794) show that Cambridge One lock rules are prone to localized database or state corruption. This results in the platform failing to enforce the restriction or causing validation loops.
- **Save State Out of Sync:** The UI may report that a rule is successfully configured or saved (as seen in Ticket 1099646 and the current ticket's screenshots), but the underlying application/database layer fails to register, process, or associate the specific content items with the rule.
- **Roster Inconsistencies:** Class roster modifications (such as removing a student who has an active user-specific rule) can break the rule-processing logic for the entire class context (COS-1424).

- **Confirmed causes:**
