# Incident Investigation Report: 1359073

## Reported Issue Summary
A VIP user is experiencing connection issues when attempting to launch assignments via the Blackboard application. While the platform support team has confirmed the user successfully completed previous activities, the user is unable to access current assignments, prompting a request for student logs to investigate the failure.

## Affected Systems
- Cambridge One (C1)
- Blackboard (LTI Integration)
- Metrica (Test/Assignment Engine)

## Common Patterns
- **Platform:** All incidents involve the Cambridge One (C1) platform integrated via LTI with external systems (Blackboard) and the Metrica engine.
- **Symptom:** Recurring "Launch failure" or "Redirect loop" caused by state synchronization errors between C1 and Metrica.
- **Technical Failure:** Frequent failures where an attempt is marked "In progress" or "Completed" in Metrica, but fails to trigger a successful launch or score update in C1.

## Root Cause Analysis
- **Confirmed causes:** None. Internal logs currently show no errors in C1 and no issues for other users.
- **Suspected causes:** A state synchronization mismatch between Cambridge One and the Metrica engine (e.g., attempt registered as "In-complete" or "Completed" in Metrica while C1 launch metadata fails to validate) is the most likely driver, consistent with historical data.
- **Missing evidence:**
    - Explicit Metrica-side status for this specific student's assignment.
    - Confirmation if the student performed the activity after a class end-date (Ticket 1011710).
    - Presence of multiple launch attempts (Ticket 1013019).

## Recommended Next Steps
1. **Request Metrica Status:** Obtain the status of the specific assignment attempt from the Metrica team to check for synchronization mismatches (Reference: Ticket 1083629, 1044716).
2. **Log Correlation:** Cross-reference the student's activity timestamps against the class "End Date" to ensure session validity (Reference: Ticket 1011710).
3. **Validate Launch Metadata:** Verify if the launch action is set to "prepopulate" versus "review" (Reference: Ticket 1083629).

## Recommended Resolution
The most likely resolution is a manual push of the score payload or a reset of the user’s test attempt once the Metrica synchronization status is confirmed. This pattern has been successfully applied in tickets 1083629, 1044716, and 1013019.

## Confidence Level
**High** — The symptom is highly consistent with known LTI/Metrica synchronization failures documented in five prior investigations. The current observation that the student "already has scores" suggests a classic state-conflict issue where the system is stuck between completion and access.
