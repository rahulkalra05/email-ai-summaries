# Operational Incident Investigation Report

## Incident Number
1362693

## Reported Issue Summary
A school administrator, Kate Austin (kausti12@jccc.edu), reported that they are unable to create External Tool links in Canvas assignments for Units 6 and 7 within the class "Reading 4 – EAP 077" (Class Key: gt3X-N2V8). While links for Units 1–5 were successfully created, attempting to add links for Units 6 and 7 results in a success message from Canvas, but no actual content populates or loads afterward.

## Initial Assessment
Based on the current incident details, the likely affected systems, products, and components are:
*   **LMS Platform:** Canvas (specifically LTI integration workflow)
*   **Platform / Product:** Cambridge One (ELT Platform Support)
*   **Integration Standard:** LTI (External Tool Links)
*   **Affected Components:** External Tool URL creation, content provisioning/rendering within assignments, and potentially underlying class rules or product association within the LMS class structure.

## Common Patterns Identified
*   **Platform-Wide Integration Failures:** Across multiple tickets (1096269, 953545, 1239653), the core issue involves the hand-shake between Cambridge One and external LMS environments (Canvas, Blackboard, Brightspace) via LTI, which prevents content from rendering or populating.
*   **Product/Material Association Corruption:** Issues where users cannot see or create content often point to a breakdown in product mapping or corrupted class configurations (Ticket 1239653, 1219125).
*   **"Re-Add Material" Resolution Pattern:** Multiple historical incidents (Ticket 1239653, 1072347) highlight that re-associating or "re-adding" the product/materials within the class configuration is the standard administrative workaround to restore content visibility and link loading.

## Root Cause Analysis

*   **Confirmed causes:** None at this initial stage of the investigation, as logs and database records for Class Key `gt3X-N2V8` have not yet been queried.
*   **Suspected causes:**
    1.  **Corrupted Class Rules / Mapping:** Similar to Ticket 1219125, there may be a corrupted or empty class rule/mapping configuration for Units 6 and 7 in the backend, preventing Canvas from pulling the external tool entities (LOs, units, or lessons).
    2.  **Product Entitlement / Access Issue:** Similar to Ticket 1239653, the class or the integration token may lack a valid association or active entitlement for the specific components of Units 6 and 7.
    3.  **LTI Class Edge Case:** Similar to Ticket 1096269, the integration may be hitting an edge case related to LTI class configurations under ongoing tracking ticket COS-1405.
*   **Missing evidence:**
    *   Application logs from the LTI launch/provisioning tool.
    *   Database records for Class Key `gt3X-N2V8` to inspect the integrity of the class rules, units, and products.
    *   Verification of the student/teacher product entitlements for the affected class.

## Actions Performed in Similar Incidents
*   **Ticket 1096269:** Support logged the incident, tracked the edge case under **COS-1405**, created **COS-1406** to develop a specific workaround for LTI classes, and recommended that ELT platform support escalate the requirement to the **Integrations team** to implement a "Re-add material" feature for LTI classes.
*   **Ticket 953545:** Support replicated the issue by creating a test learner with mismatching email casing, logged JIRA ticket **COS-827**, and had Engineering develop a hotfix to resolve the case-sensitivity mismatch.
*   **Ticket 1239653:** Checked application logs for the affected user ID, identified a "doesn't have access to either class or product" error, and performed a workaround by re-adding the product to the class.
*   **Ticket 1072347:** Technical team verified the page load failure, identified that the class was created prior to the deployment of fix **COS-1260**, and applied a workaround by selecting **Re-Add Material** in the affected class.
*   **Ticket 1219125:** Support replicated the infinite load behavior using the user's credentials, analyzed backend configurations, identified a corrupted empty class rule not linked to any entity, and manually deleted the corrupted class rule from the database.

## Recommended Investigation Steps
1.  **Database/Class Configuration Inspection (Derived from Ticket 1219125):** Inspect the backend database for Class Key `gt3X-N2V8` to check for corrupted, incomplete, or empty class rules specifically linked to Units 6 and 7.
2.  **LTI Log Analysis (Derived from Ticket 1239653):** Review the application and LTI integration logs for the Canvas LMS requests originating from Class Key `gt3X-N2V8` to check for "no access to product" or entitlement mismatch errors.
3.  **Cross-reference with COS-1405 / COS-1406 (Derived from Ticket 1096269):** Consult with the **Integrations team** to verify if this failure represents a known edge case under active investigation in JIRA ticket **COS-1405**.

## Recommended Resolution Path
If the investigation reveals a corrupted rule in the database, the **Technical/Database Team** must manually delete the corrupted class rule (as in Ticket 1219125). If it is identified as a product access configuration breakdown, the **Integrations Team** or administrator should perform the **Re-Add Material** / Product Re-association process for the class (as in Ticket 1239653 and Ticket 1072347) to force Canvas and Cambridge One to resynchronize the available units.
