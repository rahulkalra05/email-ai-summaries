# Operational Incident Investigation Report

## Incident Number
1347689

## ⚠️ Verdict
**Requires Investigation**

## Reported Issue Summary
A teacher is experiencing an issue where "LOCK" rules created under the "Manage Student Access" section for *Ready, Set, Grow! (American English) Level 1* (Home Practice section) are not taking effect. Although the platform displays a confirmation message after clicking "Save" to create the access rule, the selected exercises remain completely accessible to students as if no lock rule had been applied.

- **Affected Path/Component:** Manage Student Access > Home Practice
- **Likely Impacted Systems:** Lock rule validation service, entitlement engine, or content-locking API.

## Common Patterns Identified
Across the historical records on the Cambridge One platform, two primary technical patterns emerge for Lock Rule failures:
1. **Rule Corruption:** Lock rules can enter a corrupted state where the platform fails to properly validate entitlements or apply the locking restriction to the front-end (seen in **Ticket 1299299** and **Ticket 1312794**). Re-saving the rule often clears the error.
2. **Class Roster / State Discrepancies:** Modifying student configurations (such as removing a student who has an active user-scope lock rule) causes processing blockages or infinite loading states when attempting to evaluate or update rules (seen in **Ticket 1099646** under engineering ticket **COS-1424**).

## Root Cause Analysis

### Confirmed Causes
- **None yet confirmed** for Incident 1347689 due to a failed replication attempt.

### Suspected Causes
1. **Lock Rule Corruption:** Similar to **Ticket 1299299** and **Ticket 1312794**, the rule created by the teacher may be registered in the UI but corrupted in the backend database, preventing the entitlement evaluation engine from recognizing the restricted state.
2. **Exclusion / Non-Lockable Components:** The "Home Practice" component for this specific product course might contain items that are non-lockable, causing the rules to save but not apply. This is a known risk tracked under **NEMO-21735** (Exclude non-lockable components from Lock/unlock capability).
3. **Student Scope Mismatch:** There may be a discrepancy in the class roster (such as removed or un-enrolled students associated with current/previous rule scopes) similar to **COS-1424**, which prevents the proper execution of rule updates.

### Missing Evidence
- Server-side application and API logs during the exact time the teacher saved the rule.
- Database state of the Lock Rules associated with Class Key `92h2-mQi7`.
- Confirmation of whether any students in Class `92h2-mQi7` have been removed or have corrupted user accounts.
