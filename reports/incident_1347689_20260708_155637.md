# Operational Incident Investigation Report

## Incident Number
1347689

## ⚠️ Verdict
**Requires Investigation**

## Reported Issue Summary
The teacher is unable to apply "LOCK" access rules to the "Home Practice" section of *Ready, Set, Grow! (American English) Level 1* on Cambridge One. Although the platform displays a confirmation message indicating that the access rule was successfully created and saved, the exercises remain fully accessible to students as if no rule had been applied.

## Initial Assessment
- **Affected Platform:** Cambridge One (C1)
- **Affected Product:** Ready Set Grow! (American English) Level 1
- **Affected Class Code:** 92h2-mQi7
- **Affected Path/Component:** `Manage Student Access > Home Practice`
- **Suspected Backend Component:** Lock/Unlock Rule Engine, Entitlement/Validation Service (NEMO)

## Common Patterns Identified
1. **Rule Engine Corruption on Cambridge One:** Across multiple tickets (Ticket 1299299, Ticket 1312794), "Lock Rules" within Cambridge One became corrupted in the database, leading to either bypasses of restrictions or continuous redirect loops.
2. **"Manage Student Access" UI/State Desync:** The UI indicates that action has been taken (such as displaying "Success" messages or showing loading states), but the database fails to correctly commit, update, or enforce the corresponding rule parameters.
3. **Class Roster / User Scope Inconsistencies:** Class roster modifications (like removing a student while an active user-scoped rule exists) can disrupt the lock rule processor (Ticket 1099646, tracked under COS-1424).

## Root Cause Analysis

### Confirmed Causes
None at this stage due to the automated replication failure (login timeout).

### Suspected Causes
1. **Database Rule Corruption:** The lock rule created for the class `92h2-mQi7` may be corrupt on the backend, meaning that while the UI displays the rule as "created", the validation engine is not processing it (similar to Ticket 1299299 and Ticket 1312794).
2. **Unsupported/Non-Lockable Components:** The "Home Practice" component for *Ready Set Grow! Level 1* might contain non-lockable assets. This pattern is tracked under **NEMO-21735** (Exclude non-lockable components from Lock/unlock capability).
3. **Class Roster / Discrepancy Error:** There could be a user-scoped rule inconsistency caused by a student being unassigned or modified during the lock creation process (similar to Ticket 1099646/COS-1424).
4. **Timing/As Per Design State:** The lock rule may have been configured with start dates/times that have not yet taken effect, or were applied after the student accessed the materials (similar to Ticket 1038544).

### Missing Evidence
- Backend application/API logs for class `92h2-mQi7` during the rule creation attempt.
- Verification of the lock rule configuration in the database (e.g., retrieving the rule payload/ID).
- Student roster status (checking if any student has been removed or modified).
- Confirmation of whether the "Home Practice" component is technically lockable under current product specifications (NEMO-21735).

## Actions Performed in Similar Incidents
- **Ticket 1099646:** Replicated the lock saving behavior by adding and removing a student from the class roster. Confirmed backend behavior and linked to engineering ticket **COS-1424**.
- **Ticket 1299299 & Ticket 1312794:** Located the affected Lock Rule in the database, opened the "Manage Student Access" interface, and re-saved/updated the rule without making modifications. This action cleared the corrupted state in the database.
- **Ticket 1038544:** Verified rule creation timestamps and modification logs via API logs, cross-referencing them against student submission timestamps to confirm design-intended behavior.

## Recommended Investigation Steps
1. **Identify the Rule State:** Check database records or API logs for Class Key `92h2-mQi7` to determine if the lock rule was generated and assigned a valid Rule ID (Source: Ticket 1312794, Ticket 1299299).
2. **Perform a Force Re-Save:** Instruct the teacher (or impersonate the teacher account) to access the "Manage Student Access" interface for the affected class, make a minor edit (or no edit), and save the rule again to force a database rewrite (Source: Ticket 1299299, Ticket 1312794).
3. **Verify Component Lockability:** Cross-reference the "Home Practice" component against **NEMO-21735** to ensure it is not an excluded, non-lockable component.
4. **Check for Roster Anomalies:** Audit the student roster of class `92h2-mQi7` to verify if any student was removed or modified while lock rules were being established (Source: Ticket 1099646 / COS-1424).

## Recommended Resolution Path
1. **Immediate Workaround:** Have the support team or the teacher edit and re-save the rule. This has historically forced the platform to rebuild the rule validation schema and resolve database corruption.
2. **Engineering Escalation (RED Team / NEMO):** If re-saving does not work, escalate the ticket to the **RED team** referencing **COS-2229** and **NEMO-21735** to verify if a platform-wide rule serialization bug or component lockability limitation is preventing enforcement.
