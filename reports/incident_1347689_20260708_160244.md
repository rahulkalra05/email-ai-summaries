# Operational Incident Investigation Report

## Incident Number
1347689

## ⚠️ Verdict
**Requires Investigation**

## Reported Issue Summary
A teacher reports that "Lock" rules created for "Ready Set Grow! (American English) Level 1 - Home Practice" are not functioning as expected. Despite the system generating a confirmation of the rule creation, students are still able to access the exercises, rendering the restriction ineffective.

## Initial Assessment
The affected product is *Ready Set Grow! (American English) Level 1*. The issue is localized to the "Manage Student Access" feature within the Cambridge One platform, specifically impacting the persistence and validation of "Lock" rules.

## Common Patterns Identified
*   **Rule Corruption:** A recurring pattern where existing "Lock" rules suffer from internal corruption, causing entitlement/validation failures (Tickets 1299299, 1312794).
*   **Processing Errors:** Systemic failures where the backend fails to apply rules correctly when user scopes change (Ticket 1099646).
*   **UI/Save Discrepancies:** The platform may indicate success (or show a "Save" success message) while the backend fails to propagate or validate the state (Ticket 1102122).

## Root Cause Analysis
*   **Confirmed causes:** None at this time.
*   **Suspected causes:** Corruption of the specific "Lock Rule" associated with the class, or a failure in the rule-processing engine that prevents the configuration from syncing with student entitlements.
*   **Missing evidence:** Server-side application logs for the specific `Rule ID` and Class Key (`92h2-mQi7`), and confirmation of whether the rule exists in the database as intended.

*   **Ticket 1299299:** Replicated using affected user account; opened and re-saved the existing "Lock Rule" to clear corruption.
*   **Ticket 1312794:** Located corrupted Rule ID, re-saved without parameter changes; tracked under **COS-2229** (RED team).
*   **Ticket 1038544:** Verified rule creation timestamps via **API logs**; cross-referenced with student submission timestamps.
*   **Ticket 1102122:** Reviewed application logs; issue determined to be a transient state.

## Recommended Investigation Steps
1.  **Retrieve Rule Metadata:** Access backend logs to check the status of the "Lock Rule" for Class Key `92h2-mQi7` (Reference: Ticket 1038544).
2.  **Verify Rule Integrity:** Check if the specific Rule ID associated with this class is showing signs of corruption (Reference: Ticket 1312794).
3.  **Attempt Force-Save:** Open the existing lock rule and re-save it without modifying parameters to see if it clears the error state (Reference: Ticket 1299299).
4.  **Check for Removed Users:** Verify if any learners associated with previous user-scope rules were removed from the class, which might be blocking rule processing (Reference: Ticket 1099646 / COS-1424).

## Recommended Resolution Path
If the rule is confirmed as corrupted, performing an "edit and save" of the existing rule is the established resolution path to clear the entitlement state. If the issue persists, escalate to the **RED team** referencing **COS-2229** and the specific class/rule configuration data.
