# Operational Incident Investigation Report

## Incident Number
1365643

## ⚠️ Verdict
**Requires Investigation**

## Reported Issue Summary
A teacher is unable to access three assigned training courses on the ELT Platform. When attempting to start any of these courses, the user interface fails to load the content and immediately reverts the user back to the "My Training" page. Browser console and back-end logs reveal an HTTP 564 status code error during this action.

## Initial Assessment
* **Likely Affected System:** Cambridge One / ELT Platform
* **Likely Affected Component:** Learning Path Service, Amazon S3 (Object Storage), User Progress (UP) API
* **Likely Affected Product:** Teacher Training Course / ELT Digital Content

## Common Patterns Identified
* **Platform:** Cambridge One / ELT Platform.
* **Symptom:** Users encounter infinite loading, silent failures, or immediate page redirects (reverting to "My Training" or dashboard pages) when launching courses or accessing progress.
* **Technical Pattern:** The underlying failure is driven by missing, uninitialized, or corrupted user state/progress files stored in S3 or Cloudant. When the backend service attempts to fetch these records and encounters a `NoSuchKey` error or an uninitialized object, it throws an API exception (such as HTTP 564 or HTTP 500), breaking the execution flow.

## Root Cause Analysis

### Confirmed Causes
* **Missing S3 Object (NoSuchKey):** The backend logs explicitly confirm that the Learning Path service failed to retrieve the user's progress file from Amazon S3 because the expected key/object does not exist, directly triggering the HTTP 564 status code response.

### Suspected Causes
* **Failed User Progress Initialization:** Similar to **Ticket 939963**, the User Progress (UP) file for user `4348c386b0a0495fb9097bad1ab333a7` may have never been initialized for these specific training courses, or an organization/entitlement sync operation failed to create the baseline S3 objects.
* **Product Entitlement Sync Desynchronization:** The product entitlement configuration may be corrupted, meaning the platform recognizes the user has the product but has not established the corresponding backend progress tracking record.

### Missing Evidence
* We need to confirm whether the S3 object is missing across all of the user's registered organizations, or if this issue is tied to a specific Org ID.
* We require the product codes for the 3 affected training courses.

## Actions Performed in Similar Incidents

* **Ticket 939963 (Missing S3 UP / HTTP 564):**
  * **Investigation:** Analyzed system events and identified missing User Progress in S3 across target organizations. Verified that the product entitlement (`twshiv1`) was linked incorrectly.
  * **Resolution:** Coordinated with the API team to manually initialize/create the UP in S3. Resolved the user-level issue by un-entitling and re-entitling the user with the product via the support admin tool.
* **Ticket 1053789 (API 500 getUserProductAnalytics):**
  * **Investigation:** Traced DLS User ID, Org ID, and Class ID using Request IDs to isolate a failure in `Analytics().getUserProductAnalytics`.
  * **Resolution:** Unenrolled and re-enrolled the learner in the class to force-reset and restore access.
* **Ticket 1234319 (Missing S3 Assets):**
  * **Investigation:** Replicated using a sample access code and verified missing S3 assets for specific Learning Objects (LOs) marked "inprocess" in the Builder UI.
  * **Resolution:** Implemented a short-term hotfix (**COS-1995** / **COS-1996**) and re-published the product to restore asset association.
* **Ticket 1054690 (Corrupt State / Update Conflict):**
  * **Investigation:** Analyzed updated LO compatibility with old user states.
  * **Resolution:** Reset the user state using a runbook provided by Compro.
* **Ticket 1012155 (Product State Limit Exceeded):**
  * **Investigation:** Identified overall product state size limit exceptions in the application logs.
  * **Resolution:** Reset the user state of the impacted accounts in the backend.

## Recommended Investigation Steps
1. **Query the Database/Logs for Entitlement & Org Context:** Locate the specific Org ID and Class ID associated with user `4348c386b0a0495fb9097bad1ab333a7` and identify the product codes of the 3 affected training courses (similar to investigations in **Ticket 939963** and **Ticket 1053789**).
2. **Verify User State and S3 Keys:** Use backend admin tools to check if any User Progress (UP) metadata or S3 object keys exist for this user-product combination.
3. **Execute Manual Replication:** Because the automated Playwright script failed due to a login timeout, perform a manual login verification using the credentials of the affected user (`4348c386b0a0495fb9097bad1ab333a7`) to observe the network request payloads under the browser developer console when clicking "Start Course".

## Recommended Resolution Path
1. **Un-entitle and Re-entitle (Primary Path):** Following the successful resolution of **Ticket 939963**, use the support admin tool to un-entitle the affected user account (`4348c386b0a0495fb9097bad1ab333a7`) from the training products, and then re-entitle them. This workflow forces the system to re-initialize and create the missing User Progress (UP) S3 object.
2. **Manual State Reset (Alternative Path):** If re-entitlement does not automatically generate the S3 object, coordinate with the Compro/API team to perform a manual reset/initialization of the user state for the affected product codes (similar to **Ticket 1054690**).

## Confidence Level
**High**

### Explanation
This incident exhibits an exact match to the technical symptoms and root cause discovered in **Ticket 939963**. In both cases, the user experiences loading failures on Cambridge One due to an API returning an HTTP 564 status code, which is directly triggered by an S3 `NoSuchKey` error indicating that the expected User Progress file does not exist. The resolution path of un-entitling and re-entitling the user to trigger progress initialization is highly likely to succeed.
